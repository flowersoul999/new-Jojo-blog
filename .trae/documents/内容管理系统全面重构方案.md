# 内容管理系统全面重构方案

## 一、Context（背景与目标）

### 现状问题
用户反馈：当前「文章撰写」与「内容管理」功能与本网站缺乏关联性，需要全面重构。

已核实的现状：
1. **「内容管理」入口失效**：导航栏「内容管理」打开的是 `src/components/features/ContentEditor.svelte`——一个通用 GitHub 文件树编辑器，默认路径 `src/content/posts`。**该目录在本地和 GitHub 均不存在（本地 `src/content/` 下只有 `memories/`、`spec/`）**，导致 GitHub Contents API 返回 404，界面显示「空目录」+ 红色报错（即用户截图所示）。
2. **「写文章」编辑器功能较完整但缺字段**：`/write/`（React `write-page.tsx`）已支持创建/编辑/发布/删除、图片压缩上传（WebP 0.8）、封面、标签、分类、日期、草稿箱、预览、导入 MD。但只暴露 posts schema 的部分字段（title/published/description/tags/category/draft/image），未暴露 `updated`、`pinned`、`pinnedOrder`、`author`、`sourceLink`、`licenseName`、`licenseUrl`、`comment`、`password`、`passwordHint`、`lang`、`aiSummary`、`aiPolished`。
3. **图片管理缺失**：上传只有「自动压缩为 WebP」，无裁剪、无替换、无集中管理界面；图片存储约定为 `public/blogs/{slug}/{hash}.webp`（write-page 发布路径）与 `public/blogs/{分类}/xxx.jpg`（既有历史目录，如 `技术总结/`、`git/`）并存。
4. **两个入口互不关联**：写文章是独立路由页，内容管理是全屏覆盖层，各自为政。

### 用户已确认的三个决策
1. **形态**：将 ContentEditor 重构为「统一内容管理中枢」——独立路由页 `/manage/`，侧边栏分模块（文章/图片/相册/回忆），文章编辑复用并增强现有 `/write/` 编辑器。
2. **图片裁剪**：裁剪+压缩一体化——上传时先进入裁剪画布（自由/预设比例），确认后压缩为 WebP，写文章与图片库共用同一裁剪组件。
3. **扩展字段**：写文章编辑器右侧元信息面板增加全部高级字段，分「基础/高级」两组，生成完整 frontmatter。

### 技术背景
- Astro 5 博客（Aemeath 主题 V3.4.0），部署 Vercel（部分环境 Cloudflare Functions，`CF_WORKERS=true`）。
- GitHub OAuth 登录（`flowersoul999/new-Jojo-blog` 仓库 main 分支），认证与内容读写 API 已具备：
  - `src/pages/api/auth/{login,callback,status,logout}.ts`
  - `src/pages/api/content/{list,read,write,delete}.ts`（`prerender=false`）
  - DEV 模式直接读写本地文件系统（`src/utils/editor-auth.ts`），生产走 GitHub Contents API。
- posts schema 定义于 `src/content.config.ts`；渲染端（`posts/[...slug].astro`、`License.astro`、`PostMeta.astro`、`content-utils.ts`）已消费全部字段——**扩展编辑器字段是纯前端增益，无需动渲染端**。
- 样式令牌：`treasure-root` / `.card` / `bg-card` / `text-brand` / `text-secondary` / `bg-brand/10`（来自 `treasure-compat.css` 的 Tailwind 映射），品牌色 `hsl(var(--hue,250),65%,55%)`。

## 二、总体架构

### 采用独立路由页 `/manage/`（替代全屏覆盖层）
| 理由 |
|---|
| 中枢是「4 个模块的应用级页面」，不是轻量浮层 |
| 相册/图片模块需要深链（`/manage/?module=gallery&album=life-fragments`），刷新/后退安全 |
| 消除旧 ContentEditor 在每页 `client:idle` 水合的浪费 |
| 站点已有 `/write/` 独立路由先例（WriteLayout + React 岛），结构同构 |

**挂载变更**：
- 新增 `src/pages/manage/index.astro`，复用 `@/layouts/WriteLayout.astro`（已有返回主页按钮 + 主题初始化 + TreasureToaster）。
- `ContentManager.svelte` 用 `client:load` 挂载。
- `Layout.astro`：删除 ContentEditor 的 import（L7）与挂载（L636）。
- `NavAccount.svelte`：桌面端（L130-140）与移动端（L188-198）「内容管理」改为 `<a href="/manage/">`，删除 `openManager()` 与 `content-editor:open` 事件。
- 删除 `src/components/features/ContentEditor.svelte`（Phase 2 末尾，/manage/ 稳定后）。

### 模块结构
```
/manage/ → ContentManager.svelte（认证守卫 + 侧边栏导航 + 模块切换）
  ├── 文章   PostManager.svelte   列表/状态/新建/删除/跳转编辑
  ├── 图片   ImageManager.svelte  目录树/网格/上传/替换/删除/引用
  ├── 相册   GalleryManager.svelte 相册列表/上传/元信息/替换/删除
  └── 回忆   MemoryManager.svelte  条目列表/编辑/删除/新建
```

## 四、关键设计

### 4.1 API 扩展（复用为主，少量新增）

1. **`list.ts` 支持 `recursive=1`**：生产用 Git Trees API（`/repos/{owner}/{name}/git/trees/{branch}?recursive=1`）按 path 前缀过滤；本地用新 `listLocalDirRecursive`。兼容现有非递归调用。
2. **新增 `GET /api/content/posts-index/`**：
   ```json
   { "posts": [{ "slug", "path", "title", "published", "draft", "pinned", "pinnedOrder",
                 "category", "tags", "updated", "image" }],
     "imageRefs": { "/blogs/技术总结/fe-fund-html.jpg": ["技术总结"] } }
   ```
   - 实现：`list(src/content/posts)` → 逐个 `read` → `parsePostMarkdown`（复用 frontmatter.ts）→ 正文正则提取 `/blogs/[^)"'\s]+` 建倒排索引。
   - **服务端 60s 内存缓存**（module 级变量 + 时间戳），避免 N+1 次 GitHub 请求。
   - 一次请求同时服务「文章模块列表」与「图片模块引用徽标」。
3. **新增 `GET /api/gallery/index/`**：服务端 import `galleryConfig`，用 `list(public/gallery/{id})` 数照片，返回 `{ albums: [{id,name,description,date,location,tags,password,cover,photoCount}] }`。
4. **不新增端点**：图片上传/替换/删除 → 复用 `write.ts`（base64）+ `delete.ts`；photos.json → 复用 `read.ts` + `write.ts`（带 sha）；文章写/删 → 复用 `write.ts` + `delete.ts`；回忆同理。

### 4.2 图片裁剪组件 `src/utils/image-crop.ts`

**形态：vanilla TS + DOM + `ensureStyles()` 全局样式注入**（沿用 GalleryUpload.ts 先例），React（write-page）与 Svelte（ImageManager/GalleryManager）双端共用。

```ts
export function cropAndCompress(file: File, opts?: {
  quality?: number;        // 默认 0.8
  maxWidth?: number;       // 默认 1920（对齐相册上传，规避 GitHub base64 体积风险）
  maxHeight?: number;
  initialRatio?: string;   // 默认 "free"
  presets?: string[];      // ["free","1:1","16:9","4:3","3:2","9:16","16:10"]
}): Promise<{ dataUrl; width; height; size }>;
```

- 弹层交互：全屏遮罩（毛玻璃）、`object-contain` 预览、可拖拽裁剪框 + 8 向手柄、比例预设 chips、缩放滑杆（局部放大裁切）、Esc/点遮罩取消、多图跳过当前张。
- 与 `image-compress.ts` 集成：复用其解码（`createImageBitmap` + `<img>` 回退）与 dataURL 转换，保证压缩算法/质量全站唯一（WebP 0.8）；压缩逻辑从「等比缩放」升级为「裁剪矩形 + 缩放」。

### 4.3 写文章编辑器增强

**`frontmatter.ts`**：`PostMeta` 扩展：
- 基础（现有）：title / published / description / tags / category / draft / image
- 高级（新增）：updated、lang（默认 "zh-CN"）、pinned、pinnedOrder（string 便于输入，build 转 number）、author、sourceLink、licenseName、licenseUrl、comment（默认 true）、password、passwordHint、aiSummary、aiPolished（默认 true）

`parsePostMarkdown` 增加对应 switch 分支；`buildPostMarkdown` 幂等规则：
- 恒输出：title / published / description / tags / category / draft / image / lang
- 仅非空/非默认才输出：updated、pinned(仅 true)、pinnedOrder、author、sourceLink、licenseName/licenseUrl、password/passwordHint、aiSummary、comment(仅 false)、aiPolished(仅 false)

这样 parse→build 往返稳定，不污染既有文件。

**`write-page.tsx`**：
1. `PostForm` / `PublishJob` 扩展全部字段；`JOB_KEY` 升版为 `"aemeath-write-publish-job-v2"`（旧快照被现有 catch 分支清理）。
2. 右侧新增「高级设置」卡片（`<details>` 折叠）：
   - 置顶开关 + 置顶序号；更新时间；作者；原文链接；授权名称+链接；评论开关；阅读密码+密码提示；语言 select；AI 摘要 textarea + AI 润色开关。
3. `?edit=slug` 预加载：挂载时解析 `location.search`，存在则 `loadPost("src/content/posts/{slug}.md")`。
4. 接入裁剪：`addFiles` 中每张本地图先 `cropAndCompress`（取消则跳过），替换原 `compressImage` 调用点；提供「直接压缩不裁剪」开关避免每次被打断。
5. 保留编辑模式下 slug 禁用。

### 4.4 各模块功能

**PostManager.svelte**：
- fetch posts-index → 列表行：封面缩略图（aspect-[16/10]，无图用品牌色占位）、title+slug、状态徽标（草稿 amber / 已发布 green / 置顶 brand）、日期、分类、标签。
- 操作：新建（`<a href="/write/">`）、编辑（`/write/?edit={slug}`）、删除（ConfirmDialog → delete.ts）。
- 筛选 chips：全部/草稿/已发布/已置顶；空态提示「本地/仓库暂无文章，点新建发布第一篇」。

**ImageManager.svelte**：
- 左列目录树（public/blogs/ 下子目录，含图片计数）；右区图片网格（aspect-square object-cover，hover 显示文件名/尺寸/「可能被 N 篇引用」）。
- 工具栏（有选中时）：上传（选目录→裁剪→写 `{dir}/{hash}.webp`）、替换（裁剪→覆盖原路径，先 read 取 sha 再 write）、删除（ConfirmDialog → delete.ts）。
- 并行 fetch：`list?path=public/blogs&recursive=1` + posts-index（引用徽标）。

**GalleryManager.svelte**：
- 左列相册卡片（cover 缩略+name+photoCount）；右区：相册信息条 + 「元信息在 src/config/galleryConfig.ts」提示。
- 上传：选图→裁剪→逐张写 `public/gallery/{id}/p-{ts}-{rand}.webp` → 合并写回 photos.json（复用 GalleryUpload.ts 的读/合并/写回逻辑，抽为 `photo-meta.ts` 或就地复用）。
- 照片操作：编辑元信息（弹层：description/date/tags）、替换（裁剪覆盖原文件名）、删除（删文件+从 photos.json 移除记录）。
- 深链支持 `/manage/?module=gallery&album={id}`。

**MemoryManager.svelte**：
- 列表：封面(16:10)+title+date+summary+[编辑][删除]；新建用模板 frontmatter。
- 编辑弹层：title、date、summary、image（文本路径）、body textarea；保存 write（带 sha）。

## 五、内容添加建议（面向网站现有设计风格）

1. **文章列表行**：封面统一 `aspect-[16/10] rounded-lg`（呼应日记 16:10 惯例），状态徽标用圆角 pill，全套毛玻璃 `.card`。
2. **图片网格**：`aspect-square object-cover` + 占位底色避免 CLS；`loading="lazy" decoding="async"`；hover 浮层显示文件名/尺寸/引用数。
3. **高级字段表单**：两列 grid，label 小号 muted，checkbox `accent-(--treasure-brand)`，`<details>` 分组折叠，密码框显示/隐藏切换。
4. **裁剪预设 chips**：pill 圆角，active `bg-brand text-white`；16:10 预设服务封面图统一比例。
5. **空状态**：图标 + 一句话提示 + 主操作按钮（沿用 write-page anon 卡排版）。
6. **封面展示优化**：文章列表与图片模块统一 16:10 裁切预览。

## 七、风险与对策
| # | 风险 | 对策 |
|---|---|---|
| R1 | 线上仓库 posts 目录可能不存在/文章存于别处（本地确实缺失，`public/blogs/{分类}/` 目录名疑似 slug） | **Phase 1 先核实**：列出 GitHub `src/content/posts`；若文章在别处，posts-index base 路径与 write-page 发布路径同步调整 |
| R2 | GitHub API 限流（posts-index N+1 读） | 服务端 60s 内存缓存 + 手动刷新失效 |
| R3 | Git Trees API 大仓库截断 | 检查 `truncated` 字段并报错 |
| R4 | PublishJob 快照结构变更 | JOB_KEY 升版 v2，旧快照 catch 清理 |
| R5 | DEV 与线上 posts 不一致（本地空） | 空态提示「本地未检出 posts，以 GitHub 为准」 |
| R6 | 裁剪弹层双端样式隔离 | ensureStyles() 注入全局样式 + id 去重 |
| R7 | 图片引用检测为字符串匹配可能误报 | 文案「可能被 N 篇引用」+ 点击展开 slug 列表 |
| R8 | 删除文章不清理其图片 | 删除确认弹层列出关联图片数，提示到图片模块清理 |
| R9 | EXIF 方向未处理（现状一致） | 裁剪弹层文案注明 |

## 八、验证方式（端到端）
1. DEV 启动 `pnpm dev`，登录后访问 `/manage/`，各模块可用；curl `/api/content/posts-index/`、`/api/gallery/index/`、`/api/content/list/?path=public/blogs&recursive=1`。
2. 发布一篇带全部高级字段的文章 → 检查 GitHub commit 中 md frontmatter；再次载入确认 parse 正确；`?edit=` 中文 slug 正常。
3. 图片上传→裁剪→落盘；替换同一路径（无 409 conflict）；删除后引用徽标更新。
4. 相册上传后 photos.json 与既有记录合并（兼容对象/数组两种格式）。
5. 回归：`/write/` 原链路（草稿箱/预览/导入 MD/粘贴图片/dev 续跑）逐项回归；导航栏登录菜单正常。
